## Goal
将当前仓库改造成一套可实际使用的、接近本机 Roxy Browser 操作体验的多账号浏览器管理系统：复用现有 Tauri 2 + React + Rust 能力，以 `D:\RoxyBrowser` 中正在使用的 Roxy Browser 作为视觉与交互参考，并将 Chromix `v152.0.7977.82` Windows x64 构建作为可配置且可启动的浏览器运行时。最终用户可以在当前应用中管理 Profile、配置代理与指纹、启动/停止浏览器，并使用统一后的 Roxy 风格工作台。

## Acceptance criteria
- 主工作台可展示 Roxy 风格的桌面布局：侧栏导航、紧凑的 Profile 列表/表格、状态信息、搜索/筛选、批量选择与批量操作；布局在常见桌面窗口尺寸下不出现文本或控件重叠。
- 新建/编辑 Profile 流程完整可用，覆盖名称、标签/备注、代理、指纹、启动页和扩展配置；保存后的数据仍由现有 Tauri IPC/Rust 后端持久化，而不是仅保存在前端临时状态。
- 设置、MCP、导入/导出和活动日志页面使用同一套 Roxy 风格视觉系统，并保留现有可用功能；已有 Profile、代理、指纹、扩展、MCP 和归档能力不因换肤而回归。
- 浏览器引擎设置能够明确识别/配置 Chromix，并支持指向本机 Chromix 可执行文件或其解压目录中的可执行文件；启动 Profile 时能沿用现有代理、独立用户数据目录、CDP 连接和关闭流程。
- 在 Windows x64 环境准备 Chromix `v152.0.7977.82` 后，至少完成一次真实启动验证：应用能启动一个 Profile、连接 CDP、执行一个基础页面操作或状态检查，并能正常关闭；若本机缺少可运行依赖，文档必须明确记录阻塞原因和可复现验证命令。
- UI 构建命令 `npm --prefix crates/tauri-app/ui run build` 通过，Rust workspace 的 `cargo check --workspace` 通过；与改动相关的 Rust 测试通过，真实浏览器测试按环境条件执行并记录结果。
- 新增一份项目文档，记录 Roxy 参考位置、Chromix release 与校验信息、安装/配置方式、已验证平台、已知限制、数据安全注意事项、回滚/排障方式，以及每个已完成小块对应的提交记录。
- 每个可独立验收的小块完成后创建一个语义清晰的 Git 提交，并推送到当前分支对应的 `origin/main`；推送失败时保留本地提交并在文档与最终报告中记录失败原因，不伪造已推送状态。
- 交付前工作区除明确的交付改动外没有临时文件、下载包或调试产物；最终报告列出修改文件、验证命令、真实浏览器验证结果和未解决事项。

## Useful notes
- 当前仓库是 Cloaksession：UI 在 `crates/tauri-app/ui`，技术栈为 React 19、TypeScript、Vite 6、Tailwind CSS 4、Lucide；后端为 Rust/Tauri 2，已有 Profile、代理、指纹、扩展、归档、MCP、CDP 和浏览器启动器。
- 当前浏览器引擎模型只有 `Cloakbrowser` 与 `Cft`；Chromix 是 Chromium 兼容发行包，Windows release 资产名为 `chromix-win-x64.zip`，应以外部运行时方式集成，不把约 200MB 浏览器二进制提交进仓库。
- 本机 Roxy 安装目录为 `D:\RoxyBrowser`，主程序为 `D:\RoxyBrowser\RoxyBrowser.exe`，目录只作为视觉参考和只读调查对象；不修改、替换、卸载或强制关闭用户现有 Roxy 进程。
- Roxy 的专有代码、二进制和品牌资源不复制进仓库；实现以观察到的布局和交互模式为参考，使用当前项目代码和可再分发资源。
- Goal X 获批前不修改代码、不下载大体积运行时、不提交、不推送；获批后优先小范围推进，并在每个阶段运行与该阶段风险匹配的验证。
- 代理协作以当前环境实际可用的 Grok/Gemini 子代理为准；若运行环境未提供代理调用能力，则由主代理完成同等的并行检索、实现和审查，不因工具缺失伪造协作结果。

## Boundaries
- 只在当前工作区修改项目交付文件；临时脚本、下载包、截图和中间产物放在会话 scratch 目录，完成后清理。
- 不重写或删除现有业务数据，不破坏用户已有 Profile、浏览器数据目录、代理凭据和 MCP 配置；涉及数据迁移时必须可回滚并有测试。
- 不将 Roxy 安装目录、Chromix 二进制或第三方受限资源复制到仓库；不默认改变用户系统浏览器、代理、网络或安全设置。
- 以 Windows 本地体验为第一验收平台，同时尽量保持现有跨平台编译路径；不在没有对应运行时证据时宣称 macOS/Linux 的真实浏览器行为已验证。
- 不把界面换肤描述成匿名、防检测或安全保证；保留并在文档中说明现有指纹、CDP、代理和浏览器内核能力的实际限制。
- Git 推送仅针对当前仓库当前分支的 `origin/main`，不执行强制推送、不重写历史、不使用破坏性清理命令。
